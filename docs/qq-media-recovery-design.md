# QQ 图片占位修复与受限媒体回源设计

日期：2026-07-26
状态：已确认，待实施

## 1. 背景与证据

现有图片持久化会扫描消息正文中的所有 `img,canvas,video,svg`。真实样本中，原消息声明图片尺寸为 `864 x 1920`，插件却把 QQ 的 `60 x 60` 加载动画保存为 846 字节 PNG，并在恢复时沿用原消息宽高显示，最终形成永久转圈气泡。

该消息仍保留 `/download?appid=1407&fileid=...&spec=0`，但直接请求 QQ 媒体服务返回 `invalid rkey`。因此不能只用 `fileUuid` 拼接下载地址；网络回源必须使用 QQ 页面当前生成、包含有效 `rkey` 的完整临时 URL。

## 2. 目标

- 不再把加载动画、头像、灰色提示、视频或 SVG 当作图片副本保存。
- 对历史静态降级 PNG 执行尺寸比例校验，错误占位图不再恢复成永久转圈气泡。
- 本地图片不可用时，默认尝试从当前 QQ 会话中的受限媒体 URL 回源。
- 在管理窗口提供“缺失媒体自动回源”开关，默认开启。
- 下载成功后继续使用现有 SHA-256 内容寻址、原子写入、引用清理和存储迁移机制。
- 保持 IPC 为固定窄接口，不形成任意 URL 下载能力。

## 3. 非目标

- 本轮不增加语音、视频、文件或合并转发恢复。
- 不解析或调用未验证的 QQ 内部下载 RPC。
- 不长期保存包含 `rkey` 的完整 URL，不在日志中输出 URL、`fileid` 或 `rkey`。
- 不自动删除或改写现有记录文件；无效历史媒体只在读取时忽略。
- 不承诺恢复已经没有本地文件、没有有效完整 URL 且 `rkey` 已过期的历史图片。

## 4. 总体方案

采用“本地优先、受限回源、静态快照兜底”的固定顺序：

1. 优先使用消息元素中仍存在且大小匹配的 QQ 本地图片路径。
2. 本地路径不可用时，使用消息正文或撤回前 DOM 快照中的完整 QQ HTTPS 媒体 URL。
3. 网络关闭、URL 无效或下载失败时，只对已经加载完成的真实图片节点生成 Canvas PNG。
4. 三条路径都失败时保留撤回提示，并在有限重试结束后显示“图片暂不可用”，不保存加载动画。

网络回源设置只控制第 2 步；关闭网络不会影响本地图片、`appimg:` 原件或有效 Canvas PNG。

## 5. 组件设计

### 5.1 媒体候选捕获

`src/ui/media-capture.mjs` 调整为每个真实媒体容器最多产生一个候选：

- 只处理位于 `.pic-element`、类名包含 `pic-element` 或 `market-face` 的容器内的 `img` 和 `canvas`。
- 排除 `.gray-tip-message`、头像以及类名包含 `avatar`、`loading`、`spinner` 的节点。
- 不再把 `video`、`svg` 加入图片媒体序号。
- `appimg:` 节点继续上报本地 URL。
- HTTPS 节点即使尚未加载完成，也可以上报完整 URL作为网络候选。
- Canvas 降级只接受已加载完成的图片：`complete === true`，自然宽高均大于 0，且 Canvas 导出成功。
- Canvas 候选携带捕获宽高；节点引用仅留在渲染进程，用于成功后更新当前气泡，不进入 IPC。

同一消息按媒体容器的 DOM 顺序编号，保证 `mediaIndex` 与 `pendingMedia` 中的图片/商城表情顺序一致。

### 5.2 静态图片有效性校验

主进程在保存 Canvas PNG 前，将捕获宽高与待恢复 `picElement.picWidth/picHeight` 比较：

- 宽高必须为正整数。
- 原消息宽高均有效时，捕获图和原图的宽高比相对误差不得超过 15%。
- 原消息缺少宽高时，只依赖真实媒体容器、加载完成状态和排除规则，不使用固定最小尺寸，以免误伤小表情。

读取历史 `staticFallback: true` PNG 时，从 PNG IHDR 读取实际宽高并执行相同的比例校验。失败时丢弃该媒体元素；如果消息没有其他可恢复内容，则保留 QQ 撤回提示，不渲染图片气泡。

### 5.3 网络回源服务

新增单一职责模块 `src/core/qq-media-fetch.js`。模块接收已经注入的 Electron 网络请求函数：生产环境由 IPC 事件的 `event.sender.session.fetch` 提供并绑定当前 QQ 窗口会话，测试使用本地假响应，不依赖全局 `fetch`。当前会话没有 `session.fetch` 时，本次网络候选按不可用处理并继续本地降级，不退回无登录态的普通 Node 请求。

请求必须同时满足：

- 协议为 `https:`，端口为空或 443，不含用户名和密码。
- 初始主机只能是 `multimedia.nt.qq.com.cn` 或 `gchat.qpic.cn`。
- 路径严格等于 `/download`。
- 查询参数必须包含数字 `appid`、非空 `fileid`、数字 `spec` 和非空 `rkey`。
- `fileid` 必须与当前 `pendingMedia` 元素中的 `fileUuid` 完全一致。
- 最多跟随 2 次重定向；重定向仍须为 HTTPS，且主机必须属于 `.qq.com`、`.qpic.cn` 或 `.gtimg.cn`。
- 单次请求 10 秒超时，响应最多 20 MiB；超限立即中止。
- 响应内容按 magic bytes 识别 GIF、PNG、JPEG 或 WebP，不信任扩展名和响应 MIME。

完整 URL 只存在于当前内存候选和请求生命周期中。成功后仅保存媒体字节及既有固定引用字段。

### 5.4 IPC 与处理器

沿用 `persist-rendered-media` IPC，不新增通用下载接口：

- `appimg:` 输入继续走现有本地路径校验。
- Canvas 输入增加固定 `width`、`height` 字段。
- HTTPS 输入仍只包含 `messageId`、`mediaIndex`、`sourceUrl`，主进程再与 `pendingMedia` 中的 `fileUuid` 交叉验证。
- 网络设置关闭时，HTTPS 输入返回明确的“网络回源已关闭”错误，不发请求。
- 下载、魔数校验和保存成功后，调用现有 `processor.persistRenderedMedia()` 更新记录。

成功响应额外返回由主进程根据已验证本地文件生成的 `displayUrl`。渲染进程只把该 URL 应用于当前消息中与 `mediaIndex` 对应的媒体节点，不接受调用方指定目标路径。

### 5.5 有限重试和当前气泡

`src/renderer.mjs` 对 `memoryOnly` 图片在 0、250、1000、3000、8000 毫秒执行有限捕获：

- 同一有效 URL 或内容哈希只提交一次。
- IPC 失败时允许后续时间点重试。
- 成功后立即停止该媒体的重试，并用 `displayUrl` 更新当前气泡。
- 最后一次仍失败且当前节点只是加载状态时，将其替换为“图片暂不可用”，停止永久转圈。

### 5.6 设置存储与管理界面

新增 `settings.json`，固定保存在默认插件数据目录而不是可迁移记录目录：

```json
{
  "version": 1,
  "networkMediaRecovery": true
}
```

- 文件不存在、损坏或字段缺失时，`networkMediaRecovery` 默认为 `true`。
- 写入使用同目录临时文件加原子重命名。
- 管理窗口通过独立的固定 IPC 读取和更新该布尔值。
- UI 使用开关控件，文案为“缺失媒体自动回源”，说明为“本地副本不可用时尝试从 QQ 媒体服务恢复”。
- 关闭后立即影响新请求；已经落盘的媒体继续本地使用。

### 5.7 静态审计和文档

`scripts/static-audit.js` 从“所有生产源码禁止网络”调整为：

- 只有 `src/core/qq-media-fetch.js` 可以引用受控 Electron 网络请求。
- 其他 `src/` 文件继续禁止 `fetch`、WebSocket、HTTP/HTTPS/TCP/UDP 模块和网络 URL 字面量。
- 审计显式检查回源模块包含 HTTPS、主机、路径、fileid、rkey、超时、大小和重定向限制。

同步更新 README、架构、安全审计、安装说明和测试矩阵，明确默认联网行为、关闭入口、请求范围以及不会长期保存临时凭据。

## 6. 错误处理

- URL 缺少 `rkey`：跳过网络候选，不尝试拼接或猜测凭据。
- URL 主机、路径或 `fileid` 不匹配：拒绝并记录不含敏感参数的诊断类型。
- 超时、断网、HTTP 错误或重定向越界：中止本次请求，允许剩余时间点重试。
- 超过 20 MiB、未知魔数或静态图片比例异常：不写文件、不更新记录。
- 文件写入失败：保持现有记录和内存候选不变。
- 历史错误占位图：读取时忽略，不自动修改原 JSON 和媒体文件。

## 7. 测试与验收

### 7.1 自动化

- `60 x 60` 加载动画不能匹配 `864 x 1920` 原图，保存和历史读取均被拒绝。
- 匹配宽高比的有效 Canvas PNG 可以保存，小尺寸方形表情不因绝对尺寸被拒绝。
- `video`、`svg`、头像、灰色提示和 loading/spinner 节点不进入图片媒体序号。
- 网络开关缺失时默认为开，切换后原子持久化，关闭时不调用网络函数。
- HTTPS URL 覆盖协议、端口、凭据、主机、路径、appid、fileid、spec、rkey 和 pending 元素匹配。
- 覆盖超时、20 MiB 上限、重定向边界、HTTP 错误、伪造 MIME、未知魔数和有效图片。
- URL 和 `rkey` 不进入记录文件、日志或公开 IPC 返回值。
- 当前气泡在成功后应用 `displayUrl`，最终失败后停止转圈。
- 现有 Node 测试、静态审计和包校验全部通过。

### 7.2 实机验收

使用新测试图片完成以下矩阵，不操作既有正式记录：

1. 网络开启，本地原图存在：不发网络请求，撤回后立即显示，切换会话和重启后仍可用。
2. 网络开启，本地原图不可用但完整 URL 含有效 `rkey`：受限回源成功并落盘，当前气泡停止转圈。
3. 网络关闭，本地原图不可用：不发请求，有限重试后显示“图片暂不可用”。
4. 加载动画存在：不得在 `media/` 生成对应占位 PNG。
5. 删除测试会话：最后引用删除后媒体副本被清理。

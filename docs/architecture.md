# 架构说明

## 数据流

1. 主进程包装 QQ `webContents.send`，只读取本地 Electron IPC 中的消息列表。
2. 支持的消息进入 10,000 条先进先出内存缓存；图片和表情候选先保留真实元素与路径。最近 2 分钟内的新普通图片缺少本地文件时，主进程通过 QQ 原生消息服务按 `msgId`、`chatType`、`peerUid` 与 `elementId` 请求原图，并把校验后的 SHA-256 媒体引用绑定到内存候选；重复列表更新复用同一引用。
3. 收到撤回灰条时，以消息 ID 查找原消息；保留撤回包的序列、客户端序列和发送状态，并恢复原消息的 `msgAttrs`、`msgMeta`、`generalFlags` 特殊类型后发往渲染层。
4. 对仅靠页面快照恢复的图片/表情，渲染层按真实媒体容器上报 `appimg:`、完整 QQ HTTPS 临时地址或已加载完成的 Canvas PNG。主进程将候选与当前 `pendingMedia` 的 `fileUuid` 和原图尺寸交叉校验。
5. 插件加载早于 QQ `application.asar`，因此只包装 QQ 自己加载的 `wrapper.node` 导出以记录当前原生 session，不主动加载原生模块。后台预取监听 `onRichMediaDownloadComplete`，只接受同时匹配候选 `msgId` 与 `elementId` 的完成事件，30 秒超时后移除监听。渲染层上报的完整 HTTPS 临时地址仍由 IPC 发送方窗口的 `session.fetch` 受限回源；缺少 `rkey` 的相对地址直接拒绝。成功字节按魔数识别并以 SHA-256 保存到 `media/`，记录中不保留临时 URL。
6. 重新打开对话或 QQ 重启后，撤回灰条再次出现时，从本地记录恢复消息，并按当前记录根校验媒体相对路径、大小、SHA-256 和历史静态 PNG 比例后重建本地路径；校验通过的普通图片在恢复对象中标记 `transferStatus=4`。若记录中的 QQ `thumbPath` 已无任何有效文件，则仅在本次恢复对象中以已验证原图作为 `0` 号缩略图；仍有有效缩略图时保留原映射。

图片与图片表情恢复优先复用 `picElement` 已携带的有效本地路径；商城表情优先复用 `marketFaceElement` 的本地路径。仅靠页面快照恢复时标记为 `memoryOnly`；消息登记为已撤回后锁住最后一份撤回前快照，不再让 QQ 后续生成的加载失败节点覆盖它。当前会话内存候选可保留 `originImageUrl` 供恢复和受限回源，持久化前再次清洗并删除。随后依次尝试严格位于 QQ `Pic/Emoji` 下的 `appimg:` 原件、当前会话完整 QQ 媒体地址和已加载完成的 Canvas PNG。带有效原图尺寸时，PNG 候选除 15% 宽高比校验外，还会拒绝 64×64 以内且原图任一边大于 128 的加载占位；缺少原图尺寸的小表情不设绝对最小尺寸。渲染层在 0、250、1000、3000、8000 毫秒有限重试，最后仍为加载状态时显示“图片暂不可用”。

## 存储

当前记录根包含 `records/`、`media/` 和 `ptt/`：图片媒体单项上限 20 MiB，按真实 GIF/PNG/JPEG/WebP 魔数确定扩展名并以 SHA-256 去重；尚未撤回的预取图片由内存候选引用，候选淘汰时清理未被其他候选或正式记录引用的副本。语音（1.4.1 起）保存在 `ptt/`，同样 20 MiB 上限、AMR/SILK 魔数校验和 SHA-256 去重。设置页面选择新目录时先复制仍被记录引用的媒体，再切换记录和媒体根；孤儿媒体不迁移，失败时旧根继续生效，旧目录不会自动删除。切换回曾用过的目录时，按 `msgId` 合并两侧记录（当前会话版本优先），目标目录期间新增的记录不会丢失。

加载时无法解析的记录文件会重命名为 `<原名>.corrupt-<时间戳>` 备份保留，不会被同会话的新记录覆盖。

`settings.json` 固定保存在默认插件数据目录，不随记录根迁移；文件缺失时 `networkMediaRecovery` 默认为 `true`，文件存在但损坏或字段非法时回退为保守的 `false`（不静默重新开启网络回源）；含 `preventSelf`（默认 `false`）。写入采用同目录临时文件和原子重命名。

管理窗口通过独立的 `qqLocalRecallManager` Preload 桥接获得固定接口，不能传入或读取任意文件路径。删除会话或单条记录时同时更新记录、内存候选和媒体引用，并广播 `records-deleted` 供聊天窗口同步；共享内容仍被其他记录引用时保留，最后引用删除后清理媒体文件。管理页展开会话时显示每条记录的文字片段、语音时长和图片缩略预览；缩略图字节由主进程按已验证的 SHA-256 引用读取（上限 8 MiB）并以 data URL 返回。插件启动与管理页会读取 QQ `versions/config.json` 的当前版本，与已验证版本（`9.9.32-51246`）不一致时给出提示但不阻止运行。

## 渲染层

渲染层接收已恢复消息 ID、内容类型（消息/图片/语音）、操作者角色/名称、原发送者名称、`memoryOnly` 和已删除消息 ID。`operatorRole=0/1/2` 分别按普通成员、管理员、群主呈现；提示按内容类型区分“尝试撤回此消息/此图片/此语音”，管理员或群主撤回他人消息显示“尝试撤回 发送者 的信息/图片”。渲染层在消息仍可见时保存图片节点快照，`memoryOnly` 恢复时按消息 ID 回填；提示文案未变化时不写 `textContent`，切换会话后没有对应消息行的孤立提示会被移除，避免残留到其他会话或触发 `MutationObserver` 循环。管理窗口启用 `contextIsolation`、`sandbox` 并禁用 `nodeIntegration`。
